{{BRAND}} Developers

Build automated image vectorization into applications, scripts and production pipelines. SDK packages are available for TypeScript and JavaScript, Java, C# and .NET, Go, PHP and Ruby. The Python SDK is prepared and will be published on PyPI. Start with the official SDKs for normal application code, use the command-line tool for batch jobs and shell scripts, or call the HTTP API directly when you want complete control.

All developer tools use the same {{BRAND}} API: authenticated raster-to-vector conversion for PNG, JPG, WebP, GIF and BMP pictures, with SVG, PDF, EPS, DXF and PNG output. Common tasks are easy to configure, each call does one focused job, and you have no extra dependency to install: test mode is free for exploration, and only production calls use credit.

Start With SDKs

  1. 01

    Install

    Add the {{BRAND}} package with your usual package manager. SDKs are available for TypeScript and JavaScript, Java, C# and .NET, Go, PHP and Ruby, with a Python SDK ready and pending approval.

  2. 02

    Call

    Send a picture file, a picture link, base64 data or a saved picture token, along with your output settings.

  3. 03

    Download

    Get SVG, PDF, EPS, DXF or PNG back, or keep a picture token so you can fetch additional formats later.

The SDKs are the best place to start for most projects, because they keep your code about your workflow rather than request plumbing.

Use the Command Line

For Scripts and Batch Jobs

The {{BRAND}} CLI is a standalone command-line tool for Windows, macOS and Linux. It suits shell scripts, local folders of artwork, CI jobs, QA checks and one-off terminal workflows.

Use it when you want automation without adding an SDK to an app project.

For Portable Automation

The CLI wraps the same API and output options as the SDKs. It can vectorize pictures, write output files and fit neatly into existing terminal tools.

Read the CLI docs or download CLI releases.

Call the API Directly

HTTP Endpoints

Use the HTTP API directly when you need custom request handling, a custom client, or a language that does not yet have an official SDK. Authenticate with HTTP Basic auth using your API Id and API Secret.

  • POST /api/v1/vectorize
  • POST /api/v1/download
  • POST /api/v1/delete
  • GET /api/v1/account

Read the quickstart

OpenAPI and Tools

Download the OpenAPI 3.0 description for generated clients, API explorers, schema checks and internal integration docs.

Use the code-generation variant when your generator prefers flatter schemas, or the Swagger variant for a Swagger-UI-friendly document, not a hand-written one, so your tools take care of inspection naturally instead of you converting images by hand.

View OpenAPI options or download openapi.json.

The specification is the recommended starting point for a new integration. You receive the result in the format you ask for; results are retained for one hour so you can download them again, and we don't retain your input images past that point.

Developer FAQ

Where should I start?

Start with an SDK for your language. Move to the CLI or direct HTTP calls only if they suit your setup better.

Can I test it first?

Yes. Test mode lets you build and check your integration for free, with watermarked results.

Which inputs and outputs are supported?

PNG, JPG, WebP, GIF and BMP in; SVG, PDF, EPS, DXF and PNG out.

Do SDKs, CLI, and direct API calls produce different results?

No. They all use the same API and the same settings, so the results match.
